# 0049 — Nemotron 3.5 ASR Streaming 0.6B: a second, real STT provider

## Status

Accepted (2026-09-12), R2 (research roadmap, post-GA — third of R0-R3,
standing autonomous GO per `[[github-workflow-autonomy]]`).

## Context

R1 (ADR-0048) proved, for diarization, that the pattern R0 built (a
provider-agnostic interface + factory-based selection via a
`VOCADOX_<X>_PROVIDER` env var) repeats cleanly for a second real
provider. R1's own report recommended R2 follow the exact same shape for
speech-to-text: add NVIDIA's Nemotron 3.5 ASR Streaming 0.6B
(`nvidia/nemotron-3.5-asr-streaming-0.6b`) alongside `faster-whisper` as a
second, real `SpeechToTextProvider`.

Unlike R0/R1, this model ships under **OpenMDW-1.1**, a license this
project had never evaluated before (faster-whisper is MIT, pyannote is
MIT, Sortformer is CC BY 4.0, Ollama/Qwen is Apache-2.0). Per this
project's standing "verify before building" discipline (ADR-0017's
pyannote 3.x→4.x reversal, R0's FastMSS-is-not-TTS correction, R1's
gated-field discrepancy), the license had to be read directly — not
assumed equivalent to a standard permissive license from a research
summary — **before any integration code was written.**

## Decision

### License: OpenMDW-1.1 — read directly, no blocker found

Two independent sources fetched and read directly, 2026-09-12:

1. The model card's own "Governing Terms" line: "Use of the model is
   governed by the OpenMDW-1.1 license", linking to
   `https://openmdw.ai/license/1-1/`.
2. The Hugging Face model API (`GET
   https://huggingface.co/api/models/nvidia/nemotron-3.5-asr-streaming-0.6b`):
   `"gated": false`, `"license": "other"` with the `license_name` tag
   `openmdw-1.1` and `license_link` pointing at the same URL, `"sha":
   "ea30d66debe3740a08b573244286791d423d6b3e"` (the exact commit pinned
   below).
3. The full OpenMDW-1.1 license text itself, fetched directly from
   `https://openmdw.ai/license/1-1/` — the step this project's own
   discipline requires and the research letter's "weights available"
   summary alone would not have satisfied.

**What the license text actually says**, checked against every question
this project's standing model-inventory discipline requires:

- **Commercial/production use**: permitted. The grant is "free of charge,
  to deal in the Model Materials without restriction, including under all
  copyright, patent, database, and trade secret rights" — no field-of-use
  exclusion for commercial use.
- **Field-of-use / responsible-use-policy restrictions**: **none as a
  legal term.** The license text explicitly states: "This agreement does
  not impose any restrictions or obligations with respect to any use,
  modification, or sharing of any outputs generated by using the Model
  Materials." NVIDIA's model card separately carries an "Ethical
  Considerations" section referencing NVIDIA's Trustworthy AI practices
  and asking developers to ensure the model meets requirements for their
  industry/use case — this is model-card *guidance*, not a term
  incorporated into the license by reference (the license text itself
  names no such policy). This distinction is recorded explicitly, the
  same way ADR-0048 recorded the model-card-vs-HF-API gating discrepancy
  rather than silently resolving it either way.
- **Medical/healthcare/high-risk use restriction**: **none found** in the
  license text. No domain-specific carve-out of any kind.
- **Attribution requirement**: none beyond retaining, on redistribution,
  "(1) a copy of this agreement, and (2) all copyright notices and other
  notices of origin included in the Model Materials." No requirement to
  attribute NVIDIA in a product's UI, documentation, or generated output
  (contrast with Sortformer's CC-BY-4.0, which does require attribution).
- **Redistribution**: permitted, subject to the notice-retention term
  above.
- **Patent/copyright defensive termination**: rights terminate if the
  licensee files, maintains, or voluntarily joins a lawsuit asserting the
  Model Materials infringe a patent *or copyright* — broader than
  Apache-2.0's patent-only retaliation clause, but a standard defensive
  provision, not a use restriction.
- **Warranty/liability**: standard "AS IS" disclaimer, no warranty of
  merchantability/fitness/title/noninfringement/accuracy; licensee bears
  responsibility for third-party rights clearance and due diligence.

**Conclusion: no genuine license-policy blocker for VocaDox's commercial,
on-premise medical-documentation use.** This is a permissive, MIT-like
license with an added defensive litigation-termination clause and an
explicit "no output restrictions" term (helpful, not harmful, for a
product that generates clinical transcripts) — not remotely the kind of
GPL/field-of-use/responsible-use blocker Phase 2's `mutagen` rejection or
this ADR's own stop-condition would require pausing for. `nemo_toolkit`
(the runtime library, PyPI) remains Apache-2.0 (already verified in
ADR-0048 for R1; unchanged by R2, no new dependency added) — the model
WEIGHT license (OpenMDW-1.1) and the CODE license (Apache-2.0) are
recorded as two separate compliance facts, per this project's standing
"never assume identical" rule: `compliance/model-inventory.yml` carries
the OpenMDW-1.1 weight entry; `nemo_toolkit`'s Apache-2.0 is already
tracked in `dependency-inventory.yml`/`dependency-inventory-transitive.yml`
from R1, unchanged here.

### No new dependency: reuses R1's `nemo_toolkit[asr]`

Nemotron 3.5 ASR is a NeMo-native FastConformer/RNNT ASR checkpoint (model
card `library_name: nemo`) — the same `nemo_toolkit[asr]>=2.0,<3.0` extra
R1 already added to `backend/pyproject.toml`'s `[ai]` extra for Sortformer
covers ASR models too (NeMo's `asr` extra is not diarization-only). No
`pyproject.toml`/`uv.lock` change was needed for R2 — confirmed by
inspecting the extra's existing declaration before touching it, not
assumed.

### Single-file checkpoint, same shape as Sortformer

Verified directly against the Hugging Face model API's `siblings` file
listing, 2026-09-12: the repo contains `nemotron-3.5-asr-streaming-0.6b.nemo`
(the NeMo checkpoint this provider uses), `model.safetensors` (a duplicate
weight format for the `transformers`/HF path this provider does not use),
a `.gguf` quantization, and documentation/visualization assets. Not
gated (`gated: false`). `app/cli/install_models.py`'s new `stt-nemotron`
profile downloads only the `.nemo` file (`allow_patterns`), no
`dependent_repos` — materially simpler than pyannote's multi-repo
install, identical in shape to R1's `diarization-sortformer` profile.

`NemotronSpeechProvider` (`app/providers/speech_to_text.py`) loads the
checkpoint via NeMo's generic `ASRModel.restore_from()` — the standard
fully-offline single-file loader any NeMo model class supports — rather
than `from_pretrained(model_name=...)`, which would resolve against
Hugging Face at call time. This preserves the same "never let a worker
reach the network at inference time" policy every other real provider in
this codebase already enforces.

### Interface conformance: no changes needed to `SpeechToTextProvider`

Confirmed exactly as R1's own report predicted for R2. `NemotronSpeechProvider`
implements `transcribe()`/`status()` like `FasterWhisperSpeechProvider`.
Real, disclosed gaps versus faster-whisper — recorded here rather than
papered over:

- **No documented word- or segment-level timestamp/confidence API** in
  the model card's simplest documented usage sample
  (`asr_model.transcribe(["file.wav"])` → `list[str]`) — unlike
  faster-whisper's `segments`/`words` objects with per-word timing and
  probability. The whole file is reported as one `TranscriptSegment` with
  an honest `0.0` placeholder confidence and no `words`, the same "not
  fabricated" posture `PyannoteDiarizationProvider`/`SortformerDiarizationProvider`
  use for their own undocumented per-turn confidence.
- **No duration probing**: `end_seconds`/`duration_ms` are honestly
  `0.0`/`None` — adding real audio-duration detection would mean either a
  new dependency or shelling out to `ffprobe`, both out of scope for a
  PoC-scoped second provider; a genuine follow-up if this provider is
  ever promoted past PoC status.
- **`hotwords`/`initial_prompt` are accepted but unused**: no documented
  custom-vocabulary biasing API on this model card's basic usage path,
  unlike faster-whisper's native `hotwords`/`initial_prompt` parameters.
  Accepted for interface conformance only, same "not supported by this
  provider" posture `SortformerDiarizationProvider` uses for
  `min_speakers`/`max_speakers`.
- Both NeMo's plain-string and `Hypothesis`-object `.transcribe()` return
  shapes are handled defensively (some NeMo versions/model configurations
  return objects with a `.text` attribute instead of bare strings for the
  same call) — the same defensive posture R1's `PyannoteDiarizationProvider`
  uses for pyannote.audio 4.x's `DiarizeOutput` shape change.

### Provider selection: `VOCADOX_SPEECH_PROVIDER=nemotron`

`app.core.ai_providers.get_speech_provider` (the one factory function
domain code depends on — enforced by `tests/test_architecture_boundaries.py`)
now also accepts `"nemotron"`, alongside the existing `"fake"`/
`"faster_whisper"`. A separate `speech_nemotron_model_dir_name` setting
(default `speech-nemotron`) keeps faster-whisper's and Nemotron's
installed checkpoints in different `model_volume_root` subdirectories, so
an admin can have both installed side by side — same rationale as R1's
`diarization_sortformer_model_dir_name`.

## Scope: PoC, not a full eval-framework wiring — a deliberate choice

R0's DER/JER eval framework and R1's Sortformer-vs-pyannote wiring reused
`EvaluationRun`/the Evaluation Lab endpoint pattern for diarization. For
STT, this project already has a real, working WER-based comparison
(`app.analytics.wer.word_error_rate`, `EvaluationRunType.VOCABULARY_COMPARISON`,
`run_vocabulary_comparison` in `app/analytics/service.py`) — but it exists
to compare *the same provider* with/without a resolved custom vocabulary,
on one already-reviewed conversation's own audio, not to compare *two
different STT providers* against each other.

Building a genuine `SpeechToTextProvider`-vs-`SpeechToTextProvider` WER
comparison endpoint (a new `EvaluationRunType.SPEECH_ACCURACY`, wiring
`get_speech_provider`-style dual construction, fixture/ground-truth
handling analogous to R0's diarization fixtures) was **deliberately not
built in R2** — three reasons, all disclosed rather than silently
skipped:

1. **The roadmap explicitly scoped R2 as a "PoC," less integrated than
   R1's full eval-framework wiring** — the task framing this ADR responds
   to says so directly, and R1's own Sortformer wiring (`subject_b`
   reserved, no combined run) already established that even a diarization
   provider comparison stayed a "two separate runs, compared by hand"
   affair, not a single combined endpoint.
2. **No real end-to-end inference was verified for `NemotronSpeechProvider`
   in this sandbox** (see Known Limitations below) — building a
   comparison endpoint around a provider whose real transcription output
   shape is itself unverified would risk producing a "PASS" number tied
   to nothing real, exactly the rubber-stamped-synthetic-fixture problem
   R0 exists to prevent. A WER comparison is only worth building once
   there's a real transcript to feed it.
3. **Proportionality**: `run_vocabulary_comparison`'s existing machinery
   compares configs, not providers, and adapting it correctly (choosing
   which provider builds `subject_a` vs `subject_b`, deciding what ground
   truth means when one provider has no word-level output) is real design
   work, not a small addition — better done once a real Nemotron install
   exists to validate the design against, per R0/R1's own precedent of
   sequencing "infrastructure" before "cross-provider comparison."

**What R2 does not build, stated plainly**: no `EvaluationRunType.SPEECH_ACCURACY`,
no new Evaluation Lab router endpoint, no frontend comparison UI. What R2
does build: a real, swappable second `SpeechToTextProvider`, selectable by
env var, with real compliance/license tracking — the same "infrastructure
first" sequencing R0 used before R1's provider comparison, applied here in
reverse order (provider first, comparison infrastructure deferred) because
the *comparison* infrastructure (WER) already existed from post-GA P0-3
and the *provider* did not.

## Consequences

- `compliance/model-inventory.yml` records
  `nvidia/nemotron-3.5-asr-streaming-0.6b` with `bundled_with_product:
  false`, `commercial_use: true`, `redistribution: true`, `license:
  OpenMDW-1.1` — a real model entry (not a `compliance/exceptions.yml`
  dev-tool exception), since this ships in the product as a selectable
  production provider.
- `compliance/license-policy.yml`'s `approved` bucket gains `OpenMDW-1.1`,
  scoped explicitly as a model-inventory-only entry (not a PyPI/npm
  dependency license) with the full reasoning inline.
- No `backend/pyproject.toml`/`uv.lock` change — `nemo_toolkit[asr]`
  already covers this model's runtime requirements from R1.
- `docs/admin/speech-provider.md`/`docs/admin/model-installation.md` gain
  the `stt-nemotron` profile's install command and the PoC-scope
  disclosure.

## Not done in R2 (explicitly out of scope, per the task)

- **No cross-provider WER/Evaluation Lab comparison** — see "Scope" above
  for the full reasoning. `app.analytics.wer.word_error_rate` remains
  available and unmodified for a future comparison to reuse.
- **No real end-to-end Nemotron ASR inference was executed.** No GPU, no
  `nemo_toolkit` install, and no real `.nemo` download were performed in
  this session's sandbox. `NemotronSpeechProvider.transcribe()` follows
  the model card's documented usage pattern as faithfully as possible but
  is unverified end-to-end — see PHASE_R2_VALIDATION_REPORT.md for the
  full, honest account, exactly like R1's equivalent Sortformer
  disclosure.
- R3 (MFA alignment evaluation): untouched, per the task's explicit scope
  boundary; see PHASE_R2_VALIDATION_REPORT.md's recommendation.
