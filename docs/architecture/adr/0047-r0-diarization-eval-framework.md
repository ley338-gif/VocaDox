# 0047 — R0 diarization evaluation framework: metric, fixture source, and provider-agnostic interface

## Status

Accepted (2026-09-12), R0 (research roadmap, post-GA — first of R0-R3,
standing autonomous GO per `[[github-workflow-autonomy]]`).

## Context

Phase 12's GA validation report recorded an honest, non-blocking finding
(Finding #12): "genuine multi-voice diarization accuracy has never been
empirically verified anywhere in this project — every '2-speaker' test
fixture since Phase 3 used the same synthetic voice at different playback
rates, not two genuinely distinct voices." R0 exists to fix the
test-*infrastructure* gap that made this possible, so R1 (a second
diarization provider, Sortformer) and R2 (a second STT provider) can be
evaluated against real evidence instead of another rubber-stamped
synthetic fixture.

Three design questions had to be settled before writing extraction code:

1. Which diarization accuracy metric(s)?
2. Where does genuinely-multi-voice ground-truthed audio come from?
3. How does the eval mechanism avoid being pyannote-specific, given R1
   is explicitly a second provider?

## Decision

### Metric: DER + JER, both, pure stdlib

Diarization Error Rate (NIST RT-style, generalized to overlapping speech)
is the standard headline metric, but it is time-weighted — a single
dominant, correctly-diarized speaker can hide a completely missed quiet
speaker if that speaker's reference speech is a small fraction of the
total. Jaccard Error Rate (Ryant et al., DIHARD II 2019) is an unweighted
per-reference-speaker mean that does not have this blind spot. Both are
computed in `backend/app/analytics/diarization_metrics.py`, pure stdlib —
no `pyannote.metrics`/`dscore` dependency, since the metric itself needs
no ML library and adding one would pull a multi-GB dependency into the
`backend` API package just to score two lists of time ranges.
Speaker-label mapping (reference labels are arbitrary, hypothesis labels
are provider-arbitrary and must never be compared literally) is solved by
exact permutation search over the smaller label set — real diarization
runs in this project have only a handful of speakers, so this stays fast
without needing scipy's Hungarian-algorithm solver.

### Fixture source: FastMSS (dev-only), not TTS

The R0 task brief initially assumed a TTS-based synthetic-voice generator.
Verifying FastMSS's actual upstream README (2026-09-12) before writing any
extraction code found it does **not** use TTS at all — it composites real,
already-distinct human speaker recordings from an existing corpus (e.g.
LibriSpeech via a lhotse manifest) using an HMM turn-taking model, with
`boost_overlap_factor` controlling how much speakers overlap and
`save_rttm=true` emitting ground truth. This is a *better* fit for closing
Finding #12 than TTS would have been: the "same synthetic voice at
different playback rates" problem was specifically that every previous
fixture used ONE underlying voice; FastMSS mixtures use genuinely
different real speakers by construction, not a re-synthesized approximation
of that difference.

FastMSS is GPL-3.0 (`compliance/license-policy.yml`'s `blocked` bucket) —
handled as a dev-only, non-distributed, non-vendored external tool (see
`tools/dev/fastmss/README.md` and the recorded exception in
`compliance/exceptions.yml`), the same posture this project already gives
Ollama (Phase 4/12): an admin/developer installs and runs it themselves;
VocaDox's own code and shipped artifacts never contain it.

Two fixture tiers, not one, because CI has no GPU and never installs the
`ai` extra (torch/pyannote — see `.github/workflows/ci.yml`'s `backend`
job): a tiny bundled synthetic two-tone smoke set
(`backend/app/analytics/diarization_smoke_fixtures/`, generated by
`backend/scripts/generate_diarization_smoke_fixtures.py`) proves the
framework's wiring end-to-end against `FakeDiarizationProvider` in
mandatory CI; a real FastMSS-generated batch (local only, pointed to via
`VOCADOX_DIARIZATION_FIXTURES_DIR`) is what actually closes Finding #12
when run against a real provider. These are never conflated — see
`app.analytics.diarization_fixtures`'s module docstring.

### Provider-agnostic interface: reuse `DiarizationProvider`, not a new abstraction

`app.analytics.diarization_eval.run_diarization_eval` takes any
`app.providers.diarization.DiarizationProvider` — the interface Phase 3
already established (`diarize()` / `status()`), currently implemented by
`PyannoteDiarizationProvider` and `FakeDiarizationProvider`. R1's
Sortformer integration adds a third implementation of this same interface;
this eval module needs zero changes. `EvaluationRunType.DIARIZATION_ACCURACY`
reuses the existing `EvaluationRun.subject_a`/`subject_b` A/B shape
(`app.analytics.models`) rather than a new table, with `subject_b` left
`null`/reserved in R0 and populated by R1 for a pyannote-vs-Sortformer
comparison, matching every other Evaluation Lab run type's shape instead
of inventing a parallel one.

## Rejected / not selected

- **A new standalone `app.evaluation` domain / disconnected CLI script**:
  rejected per the R0 task's own explicit instruction and this project's
  established pattern (Phase 8's Evaluation Lab already exists as the
  customer-facing quality record) — a second, disconnected mechanism would
  fragment "what does VocaDox actually measure" across two places nobody
  reconciles.
- **pyannote.metrics / dscore as a dependency**: rejected — multi-GB
  transitive footprint (torch etc., already isolated to the `ai` extra)
  just to compute DER/JER, when both are well-defined, stdlib-computable
  metrics.
- **TTS-based synthetic voice fixtures** (the task brief's initial framing):
  superseded once FastMSS's actual mechanism (real-corpus compositing, not
  TTS) was confirmed from its own README — see "Fixture source" above.

## Consequences

- Real empirical validation of Finding #12 (does DER/JER actually
  differentiate cleanly across overlap levels **on real speech, through
  real pyannote**) requires a FastMSS batch + a GPU-or-CPU environment with
  the real `pyannote.audio` pipeline installed — neither is available in
  this session's sandbox or in mandatory CI. R0 ships the framework, the
  bundled metric-level proof (synthetic fixtures + a realistic
  hypothesis-degradation model prove the *metric* differentiates cleanly —
  see `backend/tests/analytics/test_diarization_metrics.py`), and a
  runnable manual runbook (`tools/dev/fastmss/`); the real-voice empirical
  run itself is an explicit, disclosed follow-up — see
  `PHASE_R0_VALIDATION_REPORT.md`'s Known Limitations and Recommendation.
- `VOCADOX_DIARIZATION_FIXTURES_DIR` is a new optional setting
  (`app.platform.config.Settings`) — unset by default and in CI, local
  filesystem path only, never a URL.
